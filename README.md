# Movies API

Асинхронное REST API для каталога фильмов. Приложение позволяет хранить
название, жанр, рейтинг и год выпуска фильма, редактировать записи и получать
подборки с фильтрацией, сортировкой и пагинацией.

Учебный проект на FastAPI с разделением маршрутов, схем валидации, моделей
и слоя работы с базой данных.

## Основные возможности

- Создание, просмотр, полное и частичное обновление, удаление фильмов.
- Фильтрация по диапазону годов выпуска и минимальному рейтингу.
- Сортировка по названию, году, рейтингу или идентификатору.
- Пагинация с помощью `limit` и `offset`.
- Валидация входных данных и ограничения целостности в SQLite.
- Версионирование схемы БД через Alembic.
- Интерактивная документация Swagger UI и ReDoc.
- Автоматические проверки API, фильтрации и ограничений базы данных.

## Быстрый старт

Понадобятся Git и Python 3.12. Все команды после клонирования выполняются
из корня проекта — рядом с `alembic.ini` и `requirements.txt`.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Ilyanesm/movies-api.git movies_api
cd movies_api
```

### 2. Создание и активация виртуального окружения

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Windows CMD:

```bat
.venv\Scripts\activate.bat
```

Linux / macOS:

```bash
source .venv/bin/activate
```

Если команда `python` недоступна, используйте `python3` в Linux / macOS
или `py -3.12` в Windows. При запрете активации PowerShell можно вызывать
`.\.venv\Scripts\python.exe` напрямую вместо `python` в следующих командах.

### 3. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

Расширение `SQLAlchemy[asyncio]` устанавливает `greenlet`, необходимый
для асинхронных сессий. Дополнительные серверы БД и переменные окружения
для локального запуска не нужны.

### 4. Применение миграций

```bash
python -m alembic upgrade head
```

Команда создаёт `movie.db`, таблицу `movies`, индексы и ограничения.
Приложение подключается к этому же файлу; таблицы создаются миграциями.
При обновлении существующей БД миграция с ограничениями сохранит записи,
если их рейтинг и год удовлетворяют новым правилам.

### 5. Запуск через Uvicorn

```bash
python -m uvicorn src.main:app --reload
```

- API: <http://127.0.0.1:8000/>
- Swagger UI: <http://127.0.0.1:8000/docs>
- ReDoc: <http://127.0.0.1:8000/redoc>
- OpenAPI: <http://127.0.0.1:8000/openapi.json>

`--reload` предназначен для разработки. Остановка сервера — `Ctrl+C`.

### 6. Запуск тестов

```bash
python -m pytest -q
```

Тесты используют отдельные временные базы SQLite с применёнными миграциями.
Проверяются CRUD, отсутствие записи, фильтрация, все варианты сортировки,
пагинация, ошибочные значения и ограничения БД при прямой SQL-вставке.

## Основные эндпоинты

| Метод | Путь | Назначение | Успешный ответ |
| --- | --- | --- | --- |
| `GET` | `/` | Проверить работу приложения | `200`, сообщение о готовности |
| `GET` | `/movies/` | Получить список фильмов | `200`, массив объектов с `id` |
| `GET` | `/movies/{movie_id}` | Получить фильм по идентификатору | `200`, объект с `id` |
| `POST` | `/movies/` | Создать фильм | `200`, созданный объект с `id` |
| `PUT` | `/movies/{movie_id}` | Полностью заменить данные фильма | `200`, поля фильма без `id` |
| `PATCH` | `/movies/{movie_id}` | Изменить переданные поля | `200`, поля фильма без `id` |
| `DELETE` | `/movies/{movie_id}` | Удалить фильм | `200`, JSON `null` |

Для отсутствующего фильма операции по идентификатору возвращают `404`
с сообщением `Фильм не найден`. Ошибки валидации возвращаются с кодом `422`.
Проверка `/` подтверждает работу HTTP-приложения и не проверяет подключение к БД.

### Создание фильма

В Swagger UI откройте `POST /movies/`, нажмите **Try it out** и передайте:

```json
{
  "title": "Начало",
  "genre": "Фантастика",
  "rating": 8.8,
  "year": 2010
}
```

Пример ответа для первой записи в новой базе:

```json
{
  "title": "Начало",
  "genre": "Фантастика",
  "rating": 8.8,
  "year": 2010,
  "id": 1
}
```

Для `PUT` передайте все четыре поля. Для `PATCH` достаточно изменяемых полей:

```json
{
  "rating": 9.0
}
```

Пропущенные поля при `PATCH` сохраняются. Явное значение `null` для любого
поля не допускается. Пустой объект `{}` не изменяет запись.

## Фильтрация и сортировка

Параметры передаются в query string запроса `GET /movies/`.
Фильтры применяются совместно, границы диапазонов включаются в результат.

| Параметр | Тип | По умолчанию | Поведение |
| --- | --- | --- | --- |
| `year_min` | `int` | Не задан | Год выпуска не меньше указанного |
| `year_max` | `int` | Не задан | Год выпуска не больше указанного |
| `min_rating` | `float` | Не задан | Рейтинг не ниже указанного |
| `order_by` | `str` | `-rating` | Поле и направление сортировки |
| `limit` | `int` | `50` | Размер страницы; приводится к диапазону 1–100 |
| `offset` | `int` | `0` | Число пропускаемых записей; отрицательное значение заменяется на 0 |

| Поле | По возрастанию | По убыванию |
| --- | --- | --- |
| Название | `title` | `-title` |
| Год выпуска | `year` | `-year` |
| Рейтинг | `rating` | `-rating` |
| Идентификатор | `id` | `-id` |

При равных значениях основного поля применяется дополнительная сортировка
по `id` по возрастанию. Неизвестное значение `order_by` заменяется на `-rating`.
Если фильтрам ничего не соответствует, API возвращает `[]`.

Пример: фильмы 2000–2020 годов с рейтингом от 7, сначала лучшие, до 10 записей:

```http
GET /movies/?year_min=2000&year_max=2020&min_rating=7&order_by=-rating&limit=10&offset=0
```

Следующая страница — тот же запрос с `offset=10`.

## Модель данных

Модель `Movie` хранится в таблице `movies`.

| Поле | Python / SQLite | Правила API |
| --- | --- | --- |
| `id` | `int` / `INTEGER` | Первичный ключ; назначается БД и возвращается при создании и чтении |
| `title` | `str` / `VARCHAR` | Обязательное название длиной 2–200 символов |
| `genre` | `str` / `VARCHAR` | Обязательный жанр длиной 2–100 символов |
| `rating` | `float` / `FLOAT` | Обязательный рейтинг от 0 до 10 включительно |
| `year` | `int` / `INTEGER` | Обязательный год от 1888 до текущего года включительно |

Схемы Pydantic: `MovieCreate` — создание и полное обновление,
`MovieUpdate` — частичное обновление, `MovieOut` — чтение с идентификатором.
Текущий год определяется при валидации. Ограничения года действуют и при `PATCH`.

## Ограничения базы данных

| Ограничение | Назначение |
| --- | --- |
| `PRIMARY KEY (id)` | Уникальный идентификатор записи |
| `NOT NULL` | Все пять столбцов должны содержать значение |
| `check_movie_rating_range` | `rating >= 0 AND rating <= 10` |
| `check_movie_year_1888` | `year >= 1888` |
| Индекс `ix_movies_id` | Индекс по идентификатору |
| Индекс `ix_movies_title` | Индекс по названию |

Ограничения `CHECK` применяются миграцией `b7c9d1e2f3a4` и защищают данные
даже при прямой записи в SQLite. Длины строк и верхняя граница года проверяются
на уровне API, а не базы. `NOT NULL` запрещает `NULL`, но сам по себе не запрещает
пустую строку. Уникальности названия нет: фильмы с одинаковыми названиями допустимы.
